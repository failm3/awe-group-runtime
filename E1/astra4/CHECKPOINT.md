## Следующий операторский шаг

1. Получить рабочую команду для существующего изолированного E1 PostgreSQL 5433. Зафиксировать ревизию исходников, runtime mission/project ID, собственный digest A1 plan/spec/grant и принадлежность тестов. Подать цель из ORACLE в ordinary ingress. Не передавать эталонные ответы в AWE.

Сопоставить счётчики уникальных попыток, fence, output refs и readbacks PG. Отдельным холодным чтением проверить сырьё для независимого oracle.
3. Передать QA реальные замороженные результаты, URI/digests, события A1/A2/A3, сведения об источнике и расходе модели, ожидаемые границы. QA самостоятельно применяет независимый эталон и отрицательный контроль. Сохранить verdict и ссылку в следующей карточке цикла. Код, написанный Sol, регистрировать в provenance разработчика. До появления работающего Coding Executor критерий CODE получает BLOCKED.
4. При ошибке записать reproducible command, первый неуспешный шаг и сохранённую попытку. После исправления повторить те же критерии. Возможный модельный dispatch с потерей ACK удерживает резерв и logical request, без слепого повтора. При исчерпании лимита или паузе сохранить run ID, checkpoint и статус для возобновления.
